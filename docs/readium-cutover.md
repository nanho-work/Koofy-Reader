# Readium 단일 리더 전환

2026-09-19. 이 문서가 기존 G1 통합·서재 패치·미사용 코드 정리 문서의 현재 상태를 대체한다.

## 전환 범위

Android와 iOS의 표지, 이어 읽기, 이전 북마크 진입은 모두 `NativeReaderLaunchPage`를 거쳐 공식 Readium을 실행한다. `/reader`는 과거 URL 호환을 위한 별칭이며 `/reader/native`와 같은 화면을 만든다. 기존 리더 선택, 기록 날짜에 따른 엔진 선택, 데스크톱용 자체 엔진 fallback은 없다. 독서는 Android/iOS에서 지원한다.

`lib/features/reader/`의 자체 페이지 계산, 화면, 컨트롤러, 검색·위치 서비스, 설정 저장 구현을 제거했다. 전용 글꼴 9개와 `wakelock_plus` 및 사용되지 않는 전이 의존성도 제거했다. 과거 기록을 읽는 직렬화 모델만 `native_reader/migration`에 남는다. 기존 구현의 테스트를 제거한 만큼 테스트 개수가 감소하므로 이전 전체 테스트 수와 단순 비교하지 않는다.

## 위치가 뒤로 밀린 이유와 수정

이전 서재 구현은 기존 기록이 있는 책을 기존 리더로 다시 보내기도 했다. 새 리더에서도 Readium이 계산한 페이지 시작 진행률이나 첫 표시 **문단**을 그대로 저장하면, 화면 위에서 시작한 긴 문단의 처음으로 이동할 수 있었다. 설정·화면 전환 이후의 추가 콜백이 보존한 앵커를 다시 덮어쓸 여지도 있었다.

이제 현재 자원의 실제 DOM 문자 범위를 읽는다. 저장하는 Locator에는 본문 href, CSS selector, 텍스트 노드 인덱스, UTF-16 문자 오프셋(`locations.koofyText`), 인용 문맥이 들어간다. 페이지 번호와 진행률은 표시용 정보다.

- 저장한 문자가 여전히 보이면 그 위치를 유지한다. 새로운 페이지에서 보이지 않을 때 새 표시 문자를 저장한다.
- 초기 열기·글자 크기·화면 변경 중에는 복원 대상 문자가 실제로 보이는지 확인한 뒤 복원을 끝낸다. 같은 장에 도착했다는 콜백만으로 성공 처리하지 않는다.
- 반복 문장이 많으면 인용문 검색만으로 위치를 구별할 수 없다. 정확한 DOM Range의 사각형을 임시 비표시 요소로 Readium의 `scrollToId`에 전달한다. 열 정렬·스크롤 이동은 SDK가 수행한다. 본문 텍스트 노드를 분할하거나 SDK 소스를 수정하지 않는다.
- 비동기 DOM 조회와 화면 변경에 세대를 부여해 오래된 조회 결과를 폐기한다. 정상 닫기는 진행 중인 위치 조회와 네이티브 체크포인트 저장을 기다린다.
- 두 플랫폼이 같은 `packages/koofy_reader_bridge/ios/Resources/reader_anchor.js`를 사용한다. Android는 이 디렉터리를 assets로 포함하고 iOS는 CocoaPods 리소스 번들로 포함한다.
- 기존의 네이티브 복구 기록 → SQLite commit → ACK 순서는 유지한다. 복구를 먼저 끝낸 다음 기존 기록 이전 여부를 판단하므로 이전 기록이 새 체크포인트를 덮어쓰지 않는다.

페이지 배치가 달라지면 같은 문장이 화면의 같은 픽셀이나 같은 쪽 번호에 나오는 것은 아니다. 합격 기준은 읽던 문자가 새 화면에 포함되고, 이동 없이 반복 재개방할 때 저장된 문자 위치가 변하지 않는 것이다.

## 기존 기록과 원본 보호

첫 실행에서 SharedPreferences의 이전 위치·북마크·설정·검색·최근 읽기 기록을 `readium_cutover_legacy_backup_v1`에 원문 그대로 한 번 백업한다. 기존 키를 정규화하거나 지우지 않는다. 백업 쓰기가 실패하면 성공으로 간주하지 않는다.

책별로 과거 정규화 본문 캐시도 `native_reader_v1/legacy_cache`에 별도 보존한다. 서재 더보기의 **이전 기록과 북마크**에서 문맥과 원본 기록을 확인한다.

TXT는 실제 변환기에 쓰는 동일한 문단·장 분할표로 이전 문자 오프셋을 새 Locator에 매핑한다. 과거 캐시와 현재 정규화 본문이 일치하고 위치가 유효할 때만 자동 이전한다. `locator.globalOffset`, 이어서 실제 `contentOffset`을 사용하며 더 앞쪽을 가리킬 수 있는 `doublePageStartOffset`으로 대체하지 않는다. 진행률만 있으면 문자 위치 0을 만들어내지 않는다.

EPUB의 과거 평문 오프셋, 손상된 기록, 본문 불일치, 검증할 캐시가 없는 기록은 자동 복원 성공으로 표시하지 않는다. 이전 진행률·문맥을 보여주고 후보 확인 또는 처음 열어 목차에서 직접 찾기를 사용자가 선택한다. 확인 전에는 새 읽기 세션을 만들지 않는다. 이미 잘못 저장된 과거 위치에서 원래 읽던 문장을 역으로 알아낼 수는 없다.

새 리더에서 읽은 뒤 원문 리비전이 바뀐 책도 알림 없이 처음으로 열지 않는다. 이전 리비전의 위치를 보존하고 변경된 책을 여는 선택을 받는다. 내장 사용 안내는 현재 제공하는 기능에 맞게 갱신했다.

확인된 TXT 북마크는 이전 기록 화면에서 눌러 Readium으로 이동할 수 있다. 이 경로는 준비된 본문의 리비전도 확인한다. 매핑할 수 없는 북마크는 원본과 문맥을 보존한다. 원본 TXT/EPUB과 준비된 EPUB의 기존 보관 정책은 유지한다.

## 검증

검증 로그는 로컬 `work/cutover-*`에 남긴다. 실제 기기와 에뮬레이터·시뮬레이터 결과를 혼용하지 않는다. 검증용 Android 가상 기기와 임시 iPad는 작업 후 종료·정리했다.

| 실행한 검증 | 결과 |
| --- | --- |
| Flutter analyze | 오류·경고 없음 |
| Flutter test | 71개 통과 |
| Android 실제 Readium instrumentation | 9개 통과, 건너뜀 없음 |
| iOS 실제 Readium XCTest | 6개 통과, 건너뜀 없음 |
| Android debug APK / iOS simulator 앱 | 빌드 성공 |
| 전체 Android 앱, 이전 TXT 기록 자동 이전 | 기존 오프셋 4000 → `p-0000011`의 문자 238로 이전 |
| 전체 앱, 720×1600 / 1600×2200 화면 번갈아 재개방 | 4회 후 Locator JSON 동일 |
| 전체 앱, 강제 종료·재실행·다음 페이지 | 재개방 후 읽기 유지, 실제 다음 이동 시 새 문자 위치 저장 |
| 실제 본문 표시 | 넓은 두 열과 좁은 한 열 캡처에서 저장된 문단 중간 위치가 화면에 포함됨을 확인 |
| 실제 폴더블 / iOS 실기기 / release 설치 | 미검증 |

전체 앱의 접근성 덤프에는 Readium이 미리 로드한 화면의 오래된 노드 좌표가 함께 나타날 수 있었다. 표시 검증에는 이를 단독 근거로 쓰지 않고 실제 스크린샷과 네이티브 DOM Range 검사를 사용했다. TalkBack/VoiceOver 실사용 적합성은 별도 검증 대상이다.

- Flutter: 서재 상태·레이아웃, 양쪽 URL의 단일 리더 진입, 기존 기록 메뉴, 위치 DB/세션/ACK, 원본 준비, 기록 백업, TXT→XHTML 문자 매핑, 모호한 기록 확인 전 실행 금지, 확인된 기록의 자동 이전을 검사한다.
- Android instrumentation: 복구 기록 검사와 실제 WebView/Readium 렌더링. 긴 문단 중간의 문자 저장, 4회 열 변경·글자 변경·닫기·재개방 후 같은 문자 표시와 체크포인트 일치, 반복 인용문의 정확한 DOM 위치 복원을 검사한다. 두 열은 실제 CSS 열 수로 확인한다.
- iOS XCTest: 실제 WKWebView/Readium에서 동일한 긴 문단·4회 재개방·열/글자 변경·모호한 인용문 복원, 복구 기록을 검사한다.
- 전체 앱: 독립된 Android 테스트 데이터로 기존 TXT 기록이 서재에서 새 리더로 이전되는 경로를 검사한다.

검증 시점에는 실제 폴더블의 USB 연결이 유지되지 않았다. 물리적으로 접기·펼치기, iOS 실기기, release 서명/설치는 별도 검증이 필요하다. 에뮬레이터의 열/화면 변경 통과를 실제 폴더블 통과라고 보고하지 않는다.

## 남아 있는 제품 범위

이 패치는 기존 렌더러를 제거하고 실행·위치 저장·이전 기록 경로를 Readium으로 통일하는 작업이다. 새 북마크 생성·본문 검색·메모 UI의 기능 확장, 사용자 글꼴 선택, TTS, 동기화, DRM, PDF/만화, CP949 입력 지원은 완료 범위에 포함하지 않는다. 현재 TXT/EPUB 입력 제한은 기존 준비 모듈과 동일하며 지원하지 않는 파일은 오류 안내를 보여준다.

사용자 기기에서 업그레이드 검증할 때 앱을 삭제하거나 앱 데이터를 초기화하지 않는다. `flutter run -d <device-id>`로 기존 앱을 갱신해 기존 위치와 북마크의 이전 과정을 확인한다.
