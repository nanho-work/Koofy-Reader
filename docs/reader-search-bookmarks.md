# 본문 검색·책갈피·가져오기 후 묶음 연결

## 제공 기능

- Android의 `찾기`, iOS의 돋보기에서 본문 검색·책갈피 추가·책갈피 목록을 연다.
- 검색은 네트워크 호출 없이 현재 Readium publication의 로컬 본문을 대상으로 수행한다. TXT도 기존 준비 모듈이 생성한 EPUB을 검색한다. 결과의 문맥을 표시하고 눌러 Readium locator로 이동한다.
- 검색어는 1~200자, 결과는 최대 500개다. 다음 결과는 `더 보기`로 불러온다. 검색을 바꾸거나 창을 닫으면 이전 작업을 취소한다.
- 책갈피는 현재의 정확한 본문 위치와 사용자 지정 이름을 저장한다. 책/내용 리비전마다 최대 100개이며 목록에서 이동·삭제한다.
- 목차·검색·책갈피로 이동한 직전 위치를 하단 되돌아가기 버튼으로 복원한다. 최근 20개를 현재 독서 세션에서만 보관한다. 일반 페이지 넘김은 이 목록에 쌓지 않는다.
- 여러 파일을 가져온 뒤 새 묶음·기존 묶음·각각 보관을 선택한다. 성공적으로 새로 추가된 책만 편집 화면에서 미리 선택하며 중복·실패 파일은 제외한다. 묶음 이름·책·순서를 확인한 뒤 저장한다.

## 저장과 호환성

Flutter SQLite를 최종 저장소로 유지한다. 스키마 v4는 `reader_positions.bookmarks_json`을 추가하며 기존 위치·전역 설정을 보존한다. 네이티브에서는 전체 책갈피 스냅샷을 기존 체크포인트 저널에 먼저 기록한다. 이후의 위치/설정/닫기 이벤트도 최신 스냅샷을 포함하므로 저널의 최신 이벤트 교체로 책갈피 변경이 빠지지 않는다.

Pigeon의 `ReaderLaunchRequest`·`ReaderEvent`에 optional `bookmarksJson` 필드를 추가했다. 저장된 구버전 저널에 필드가 없으면 기존 책갈피를 유지한다. 이전 세션/순서의 이벤트는 현재 저장 상태를 되돌리지 않는다. 동일 기기에서 한 독서 세션만 활성화하는 현재 구조를 전제로 하며 다중 기기 동시 편집 병합은 제공하지 않는다.

백업에 책갈피를 포함하고 기존 백업은 빈 책갈피로 복원한다. 현재 기기의 기존 기록을 보존하는 병합 정책은 그대로다. 백업/브리지 입력은 512 KiB, 최대 100개, 고유 ID·이름·locator href를 검증한다. 내용 리비전이 바뀌면 이전 책갈피를 새 본문에 자동 적용하지 않는다.

## 실기기 확인 항목

1. TXT와 EPUB에서 여러 장에 걸친 검색, 결과 이동, 되돌아가기. 없는 검색어, 연속 검색, 검색 중 닫기도 확인한다.
2. 목차 이동과 책갈피 이동 후 복귀. 페이지/스크롤·좁은/넓은 화면·글꼴 변경 상태를 각각 확인한다.
3. 책갈피 추가·삭제 후 앱 재실행 및 서재 백업/복원. 기존 책의 위치와 전역 설정을 확인한다.
4. 여러 파일 가져오기에서 새 묶음 생성·기존 묶음 추가·각각 보관·편집 취소. 중복/실패 파일이 섞여도 성공한 책은 유지되어야 한다.

스토어에 이미 업로드한 빌드에는 반영되지 않는다. 새 빌드가 필요하다.
