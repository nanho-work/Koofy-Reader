# iOS 단일 페이지 분할 및 복원 시간 초과 수정

## 원인

TestFlight 빌드 2에서 TXT 연속 스크롤은 동작하지만 페이지 이동이 되지 않는 문제가 발생했다. `KoofyReaderViewController.makeNavigator`가 한 페이지와 두 페이지 모두에 `--RS__colWidth: auto !important`를 적용하고 있었다.

연결된 iPhone에서 앱에 포함된 Readium CSS로 비교한 결과, 단일 열과 자동 너비의 조합에서는 본문이 가로 페이지로 분할되지 않았다. 390×704 뷰포트에서 콘텐츠 크기가 390×10000으로 남아 가로 이동이 불가능했다. 자동 너비 강제 설정을 제거하면 5850×704로 분할되고 좌표가 0→390→780으로 이동했다. iOS 시뮬레이터에서는 기존 설정도 동작했으므로 시뮬레이터 검증만으로는 발견되지 않았다.

Readium 공식 설명: <https://readium.org/css/docs/CSS03-injection_and_pagination.html>

## 변경

- 가용 너비가 충분한 두 페이지 펼침에만 자동 열 너비를 적용한다. 한 페이지 및 스크롤 모드는 Readium 기본값을 유지한다. 본문과 책장 이미지 준비용 뷰어가 같은 설정 함수를 사용한다.
- 치명적인 렌더링 오류 시 위치 복원, 이동, 시간 제한, 페이지 이미지 준비 작업을 취소하고 작업 세대를 무효화한다. 읽기 위치 복원 목표를 해제하고 대기 중인 이동 완료 콜백에는 실패를 전달한다.
- 오류 이후의 지연된 위치 콜백과 캡처 결과를 무시한다. 새 렌더링을 시작할 때만 실패 상태를 해제한다.
- 기존 30초 렌더링 제한과 10초 위치 이동 제한을 유지한다. 시간 초과 표시 이후에도 40ms 복원 재시도가 계속되는 문제를 차단한다.

## 회귀 검증

`RunnerTests`에 다음 검증을 추가했다.

- TXT 변환 형태(lang=und, section, pre-wrap)를 가진 문서와 메이플스토리 글꼴로 단일 페이지 너비, 실제 가로 분할, 앞뒤 이동을 검사한다.
- 문서 중간으로 이동한 뒤 스크롤→페이지 전환에서 동일한 본문 위치를 유지하고 다시 다음 페이지로 이동하는지 검사한다.
- 존재하지 않는 텍스트 위치를 복원하여 실제 렌더링 시간 초과를 발생시킨다. 복원 시도가 반복되었음을 확인한 뒤 시간 초과 이후 반복 횟수가 증가하지 않고 지연된 콜백도 리더를 다시 준비 상태로 만들지 않는지 검사한다.
