# 새 글 알림과 도서 화면 개선

작성: 2026-11-04. 소스 패치이며 서버·웹·스토어에는 아직 배포하지 않았다.

현재 요청: 팝업·개인정보 기능 정리만 진행한다. 푸시 설정/발송 서버 반영, 기기·듀오·폴드 실행 확인과 출시 배포는 나중에 한다. 커밋·푸시는 사용자가 진행한다.

## 화면과 다운로드

- 홈의 작은 도서 목록은 도서·서재의 열 수 계산과 표지 컴포넌트를 사용한다. 큰 홍보 캐러셀은 별도로 유지한다.
- 홈의 합본 출시 안내 상자를 제거했다. 합본 자체는 도서 목록에서 이용한다.
- 다운로드한 도서에는 체크와 ‘서재에 있음’을 표시하며, 상세 화면의 ‘읽기’로 연다.
- 다운로드는 앱 프로세스가 살아 있는 동안 화면 이동과 관계없이 순서대로 진행한다. 앱 종료 후 자동 재개하는 기능은 아니다.
- 하단 진행 상태에서 현재 작업을 취소할 수 있다. 이미 대기 중인 다른 작업은 계속 진행한다. 취소한 도서는 다시 선택해 재시도한다. 검증을 마친 파일은 재사용한다.
- 다운로드를 요청한 화면을 벗어나면 완료 후 독서 화면을 강제로 열지 않는다.
- 회차 목록은 공개 예약한 회차의 표지·제목·공개 예정일을 흐리게 표시한다. 날짜는 한국 시간으로 저장하고 기기 현지 시간으로 표시한다. 본문·본문 파일 경로는 공개 시각 전까지 제공하지 않는다.
- 오래된 앱에는 예정 회차를 전달하지 않는다. 새 앱만 `supportsUpcoming=1`로 요청한다. 관리자 초안은 예정 목록에 포함하지 않는다.
- 설정의 읽기/데이터/알림·개인정보/앱 정보 구역을 정리했다. 앱 영역의 안내·선택 팝업은 아래 공통 알림창으로 교체했다. 네이티브 독서 뷰어의 안내·확인·입력 창도 아래 공통 컨테이너에 연결했다. 독서 설정 슬라이드 패널과 검색·책갈피 관리 화면은 유지한다.

## 공통 알림창 적용

`lib/core/widgets/reader_alert.dart`를 안내·확인·선택 팝업의 공통 진입점으로 사용한다. iOS·Android가 같은 Flutter 컴포넌트를 사용한다.

- 새 글 알림의 연결/권한 오류 안내, 설정·정보 동의·백업·표지 등록·휴지통 안내, 서재와 묶음책 선택/확인에 동일한 중앙 알림창을 사용한다.
- 도서·글꼴 상세와 책 메뉴도 같은 창의 콘텐츠로 표시한다. 아래에서 올라오는 별도 시트나 하단 SnackBar를 사용하지 않는다.
- 제목·여백·색상·모서리·버튼·최대 너비를 공통화한다. 긴 내용과 큰 글씨는 스크롤되며 하단 버튼에 접근할 수 있다.
- 팝업은 루트 화면 단위로 순서대로 표시한다. 확인 중인 창 위에 비동기 안내를 겹치지 않으며, 이미 사라진 화면에서 요청한 선택창은 건너뛴다. 중복 메시지도 합친다.
- 실행 취소는 해당 안내창의 버튼으로 유지한다. 다운로드 성공은 목록의 ‘서재에 있음’ 상태로 확인하며 중복 완료 팝업은 띄우지 않는다. 가져오기 진행률과 결과 화면도 유지한다.
- OS 알림 허용창·파일 선택창·UMP 등 외부 SDK의 필수 동의 UI는 교체하거나 우회하지 않는다. 이번 변경으로 첫 실행에 새 팝업을 추가하지 않았다.

### 네이티브 독서 뷰어

- Android `ReaderAlert.kt`, iOS `ReaderAlertController.swift`를 공통 진입점으로 추가했다. Flutter와 같은 최대 너비 440, 모서리 16, 여백 24, 제목/본문/하단 버튼 구성을 적용한다.
- 다음 권 열기, 읽기 기록 저장 실패, 외부 링크 안내, 책갈피 이름 변경, 듣기 목소리 선택과 오류/안내에 적용했다. Android의 토스트 안내도 같은 창으로 연결했다.
- 같은 뷰어에서 요청한 창은 차례대로 표시하고, 닫힌 뷰어의 대기 창을 정리한다. 목소리 선택 시 듣기 설정을 잠시 닫고 선택 후 다시 열어 대기 상태에 갇히지 않게 한다.
- 입력창은 키보드 가용 영역을 고려한다. 큰 글씨/긴 메시지는 내용과 버튼 영역을 스크롤할 수 있도록 구성했다.
- 독서 설정 슬라이드 패널과 본문 검색·책갈피 관리 기능 화면은 별도로 유지한다. 이들 화면 전체를 중앙 알림창으로 바꾼 작업은 아니다.

## 알림을 받는 흐름

첫 실행에는 알림 허용 팝업을 띄우지 않는다. 설정의 ‘새 글 알림’에서 월간 쿠피 또는 새 도서 알림을 켜거나, 연재 상세에서 해당 작품 알림을 켰을 때 OS 권한을 요청한다. 거절해도 독서에 영향이 없다.

- 월간 쿠피 구독은 다음 달에도 유지한다.
- 같은 작품의 번역본은 공통 작품 ID를 사용한다. 실제 구독 주제는 앱의 한국어·영어·일본어 선택에 맞춘다.
- 구독 해제는 기기별이다. 로그인·여러 기기 간 구독 동기화는 하지 않는다.
- 언어 변경/재접속/토큰 갱신 때 구독 연결을 다시 확인한다. 실패하면 설정의 ‘알림 연결 다시 확인’으로 재시도할 수 있다.
- 백그라운드 알림을 누르면 공개 상태를 다시 조회한 후 해당 글을 연다. 비공개·삭제된 글은 열지 않는다. 앱을 사용 중일 때 독서 화면 위에 강제 팝업을 띄우지 않는다.
- 새 공개 시점에 서버 큐를 만들고 5분마다 공개 여부를 확인한다. 등록 즉시 또는 예약 시각부터 보통 다음 확인 주기에 발송 대상이 되며, OS·FCM 사정으로 전달은 지연되거나 누락될 수 있다.
- 기존 공개 작품을 편집하거나 재공개했다고 다시 발송하지 않는다. 배포 전의 기존 작품 전체를 소급 발송하지 않는다.
- FCM은 정확히 한 번 전달을 보장하지 않는다. 서버는 동일 콘텐츠의 발송을 한 번만 시도하며, 성공 여부가 불명확한 발송은 자동 재시도하지 않고 `needsReview`로 남긴다. 운영자가 임의로 `pending`으로 돌리면 중복 발송될 수 있다.

## iOS에서 먼저 할 설정

APNs 인증 키는 현재 **미등록** 상태다.

1. Apple Developer의 쿠피리더 앱 식별자 `com.koofylab.koofyreader`에서 Push Notifications 기능을 활성화한다.
2. Apple Developer → Certificates, Identifiers & Profiles → Keys에서 APNs용 키를 준비한다. 이미 다른 앱용으로 만든 같은 팀의 호환 키가 있다면 재사용 가능 여부를 확인한다.
3. Firebase Console → **koofy-reader** 프로젝트 → 프로젝트 설정 → Cloud Messaging → 쿠피리더 iOS 앱 → APNs 인증 키에 `.p8`, Key ID, Team ID를 등록한다. 키에 환경·주제 제한이 있으면 개발/운영 환경과 앱 식별자 모두 맞춰야 한다.
4. Xcode에서 Push Notifications 권한이 포함된 서명 프로파일을 갱신한다. 소스에는 `Runner.entitlements`와 Debug/Release 환경 구분이 추가되어 있다.
5. 실제 iPhone에서 구독 → 권한 허용 → 앱을 백그라운드로 이동 → 알림 수신 → 탭 후 글 열기까지 확인한다. 시뮬레이터 컴파일만으로 APNs 전달을 검증했다고 판단하지 않는다.

키·토큰은 Git이나 이 문서에 기록하지 않는다. 공식 설정 안내: https://firebase.google.com/docs/cloud-messaging/flutter/get-started

## 서버 반영 — 지금과 나중을 구분

팝업과 개인정보 원고 수정 자체에는 Firebase Functions 배포가 필요하지 않다. 앱 코드는 다음 최종 빌드에 포함하고, 공개 웹 방침은 Quiz_Site 웹 배포로 반영한다. 이번 작업에서는 어떤 배포도 실행하지 않았다.

앞서 만든 **공개 예정 회차 표시**까지 서버에 반영하려면 `readerCatalog`만 선택해서 사용자가 실행한다. 루트의 predeploy가 서버 코드를 먼저 빌드한다.

```sh
cd /Users/choenamho/Documents/GitHub/Koofy-Reader
firebase deploy --only functions:reader:readerCatalog --project koofy-reader
```

위 명령은 `reader` 코드베이스의 `readerCatalog` API만 배포하며 새 푸시 함수는 배포하지 않는다. 설치된 Firebase CLI의 함수 선택 규칙으로 선택 대상을 확인했다. 지금 당장 실행해야 한다는 뜻은 아니며 최종 기능 확인 뒤 반영해도 된다.

### 푸시 작업을 다시 진행할 때만

```sh
cd /Users/choenamho/Documents/GitHub/Koofy-Reader
firebase deploy --only functions:reader,firestore:indexes --project koofy-reader
```

이 전체 배포는 **현재 보류**한다. 새 함수 `readerQueueNewStory`(Firestore 공개 이벤트), `readerSendNewStories`(5분 주기)와 reader 코드베이스의 다른 변경까지 포함하기 때문이다.

- 먼저 위의 APNs 인증 키/서명 설정을 준비한다.
- Eventarc/Pub/Sub와 스케줄러, 실행 서비스 계정의 Firestore/FCM 권한을 확인한다.
- `readerNotificationQueue`의 `state + dueAt` 복합 인덱스가 필요하다. 클라이언트에는 이 컬렉션의 읽기·쓰기 권한을 주지 않는다.
- 배포 후 Android·iOS 실기기의 허용·거절·구독 해제·언어 변경과 수신/탭 동작을 확인한다.

## 출시 전 실기기 확인

- Android와 iOS 각각: 처음 실행할 때 자체 동의/통계/알림 팝업이 추가되지 않는지 확인한다. 필수 UMP 절차는 그대로 유지한다.
- 알림 허용·거절·구독 해제·언어 변경, 종료/백그라운드에서 알림을 눌렀을 때 이동을 확인한다.
- 예약 시각 전에는 표지와 날짜만 보이고 다운로드가 차단되는지, 공개 후 새로고침하면 읽을 수 있는지 확인한다.
- 다운로드 중 다른 탭에서 기존 책 읽기, 취소 후 다음 대기 작업 진행, 실패 후 재시도를 확인한다.
- 일반 폰/펼친 폴드/와이드/태블릿과 큰 글씨에서 표지·제목·날짜 잘림을 확인한다.
- 광고는 네이티브 독서 뷰어에만 표시한다. 이번 알림 기능은 광고 동의나 추적 권한을 우회하지 않는다.

## 앞선 작업의 검증 결과 (이번 요청 이전)

- Flutter 전체 테스트 419개 통과. 한국어·영어·일본어의 좁은 화면/넓은 화면 및 2.5배 글씨, 공통 알림창의 스크롤·확인 결과·실행 취소·중복 방지·표시 순서를 포함한다.

- Android 디버그 APK 빌드와 iOS 시뮬레이터 x86_64 빌드 통과. 공통 알림창 수정 후 폴드 에뮬레이터에 덮어 설치했다. 듀오는 번역 기능을 제외한 기존 arm64 UI 미리보기에서 실행하고 도서 정보가 중앙 공통 팝업으로 열리는 것을 확인했다. 배포 코드의 arm64 시뮬레이터 실행이나 양쪽 실기기 알림 수신을 검증한 것은 아니다.
- Firebase/스토어 배포와 커밋·푸시는 실행하지 않았다. 위의 APNs 등록·서버 반영·공개 웹 방침 반영과 실기기 확인이 출시 전 남은 작업이다.
