# 메인 서재 UI 패치

> 과거 단계의 구현·검증 기록입니다. 현재 단일 리더 전환 상태는 [Readium 전환 문서](readium-cutover.md)를 따릅니다. 아래의 기존 리더 선택·보존 설명은 현재 실행 경로가 아닙니다.

2026-09-19. Flutter 공통 서재 화면과 기존/Readium 독서 기록의 조회·재개 연결을 구현했다. 본문 엔진이나 Pigeon 계약은 변경하지 않았다.

## 화면과 동작

- 종이색 배경, 초록색 강조, 시스템 밝음/어두움 대응. 표지는 현재 책 제목을 이용한 대체 표지이며, EPUB 표지 이미지 추출은 이번 범위에 포함하지 않았다.
- 맨 위의 이어 읽기는 서재에 존재하는 책 중 최근 읽은 미완독 책 하나를 표시한다. 제목·작가·사용 가능한 장 제목·진행률·읽은 날짜를 보여준다. 기록이 없으면 독서 안내, 책이 없으면 첫 책 가져오기를 표시한다.
- 책 가져오기(TXT/EPUB), 제목·작가 검색, 전체/읽는 중/읽을 책/완독 필터, 최근 읽은 순/제목순 정렬. 정렬·필터는 화면 상태이며 앱 재시작 시 기본값으로 돌아간다.
- 표지 탭은 열기/이어 읽기, 길게 누르기와 더보기는 완독 표시·해제, 리더 선택, 삭제/숨김 메뉴다. 삭제는 별도 확인한다. 사용자가 완독을 표시해도 저장된 본문 위치를 삭제하지 않는다.
- 가져오기/열기 중 중복 요청을 막는다. 기록을 읽는 중이거나 조회에 실패하면 자동 이어 읽기를 잠시 비활성화하고 재시도를 제공한다. 조회 실패가 책 목록을 감추지는 않는다. 더보기에서 리더를 명시적으로 선택할 수 있다.
- 기존 하단 광고 영역을 유지한다. 실제 사용 가능 높이는 광고와 시스템 안전 영역을 제외한 크기다. 위젯 화면 캡처는 광고를 제외한 서재만 검사했다.

## 폴더블과 접근성

- 일반 휴대폰은 이어 읽기 → 서재의 세로 흐름이다. 가용 폭 720 이상은 왼쪽 이어 읽기와 오른쪽 서재를 함께 표시한다. 열 수는 패널 가용 폭과 글자 배율을 기준으로 정한다.
- 세로 힌지/접힘 위치가 전달되면 양 패널을 해당 경계에 배치한다. 좁은 이중 화면과 가로 힌지는 안전한 한 패널을 사용한다. 제조사별 실제 전달 값은 실기기 확인 대상이다.
- 한 스크롤 컨트롤러를 유지하고, 폭 변경 시 보이던 책 ID와 행 내부 위치를 기준으로 재배치한다. 검색어와 필터를 유지하며, 책 목록은 SliverGrid로 필요한 부분만 만든다.
- 터치 가능한 더보기와 읽기 버튼, 의미 있는 접근성 레이블, 줄바꿈 가능한 도구·필터 영역을 제공한다. 320/390/840 폭에서 글자 크기 200%를 검사한다.
- 힌지 좌표의 기준은 Flutter [DisplayFeature 문서](https://api.flutter.dev/flutter/dart-ui/DisplayFeature-class.html)를 따른다.

## 독서 기록을 연결하는 규칙

`libraryReadingStateProvider`가 기존 SharedPreferences 기록, 새 리더 SQLite 요약, 완독 표시를 조합한다. 기존 텍스트 오프셋을 Readium Locator로 변환하거나 한쪽 기록으로 다른 쪽을 덮어쓰지 않는다.

| 상태 | 표지 탭/이어 읽기 |
| --- | --- |
| 저장 기록 없는 모바일 책 | 새 Readium 리더 |
| 기존 기록이 더 최근 | 기존 리더 |
| 새 리더 기록이 더 최근 | 새 Readium 리더 |
| 날짜 없는 예전 새 리더 기록만 있음 | 새 Readium 리더, 날짜는 알려지지 않음으로 표시 |
| 날짜 없는 예전 새 리더 기록과 기존 기록이 함께 있음 | 날짜를 확인할 수 있는 기존 기록 우선 |
| 네이티브 리더 미지원 플랫폼 | 기존 리더 |

새 리더에서 서재로 돌아오면 기록을 다시 조회한다. 전체 진행률은 Locator의 `locations.totalProgression`만 사용한다. `progression`은 현재 자원 내부 비율이므로 전체 비율로 대체하지 않는다. 전체 비율이 없으면 ‘읽던 위치 저장됨’으로 표시한다. [Readium Locator 정의](https://readium.org/architecture/models/locators/)

완독은 명시적인 사용자 표시이며 진도 99% 같은 임계값으로 자동 확정하지 않는다. SharedPreferences의 `library_completion_v1:` 키 공간을 사용한다. 기존 리더의 첫 저장이 다른 책의 메모리 캐시를 빠뜨리던 문제도 수정했다.

## SQLite v1 → v2

`reader_sessions`에 nullable `started_at`(밀리초)을 추가한다. 기존 Locator·설정·세대·sequence·저널 ACK 규칙은 유지한다. 이전 세션의 날짜를 현재 시각으로 채워 넣지 않는다.

새 세션을 시작한 시각으로 최근 읽기를 정렬한다. 체크포인트를 늦게 복구해도 복구 시각이 최근 독서 시각으로 오인되지 않는다. 요약은 책별 가장 최근의 유효 Locator가 커밋된 세션을 선택하며, 열기에 실패해 위치가 없는 세션은 제외한다. 콘텐츠 버전별 Locator 복원 정책은 기존대로 유지된다.

## 검증

- 정적 분석: 이상 없음.
- Flutter 전체 테스트: 124개 통과(기존 94개 + 이번 패치 30개).
- Android 디버그 APK: 최종 소스 빌드 성공.
- iOS 시뮬레이터 앱: 최종 소스 빌드 성공.
- 한글 글꼴을 적용한 위젯 캡처에서 휴대폰·폴더블·빈 서재·다크 모드 확인.

실행 명령:

```sh
flutter analyze --no-pub
flutter test --no-pub --reporter expanded
flutter test --no-pub test/library_page_test.dart --dart-define=LIBRARY_CAPTURE_DIR=work/library-preview
flutter build apk --debug --no-pub
flutter build ios --simulator --debug --no-pub
```

신규 검사는 최근 기록과 리더 선택, 장/전체 비율 구분, 완독 저장·해제, 기존 캐시 보존, v1 DB 파일의 실제 업그레이드, 지연 체크포인트 정렬, 독서 후 진행률 갱신, 빈 서재·조회 오류·검색/필터, 큰 글자, 밝음/어두움, 세로/가로 힌지, 화면 폭 변경 시 보이던 책 복원을 포함한다.

캡처의 책·진도는 테스트용 예시 데이터다. 실제 사용자 서재에 예시 데이터를 추가하지 않는다. 위젯 테스트의 리더 경로는 대체 화면이므로 이번 검사는 네이티브 본문 렌더링의 실기기 재검증을 의미하지 않는다. 실제 폴더블 접힘/펼침, 광고가 있는 실기기에서의 터치, 기존 기록을 새 리더 형식으로 이전하는 작업은 별도 검증·구현 대상이다.


## 2026-09-21 서재 검색과 다운로드 탐색

- 앱바 검색·클라우드 아이콘을 제거하고 나의 책 아래 검색창을 항상 표시한다.
- 접힌 화면에는 `도서·글꼴 다운로드` 텍스트 버튼을 표시한다.
- 펼친 화면에는 왼쪽 이어 읽기 아래 도서/글꼴 탭을 제공한다. 오른쪽 서재의 기존 스크롤 컨트롤러/그리드 앵커를 유지하고 다운로드 목록은 독립적으로 스크롤한다. 큰 글자·짧은 화면에서는 이어 읽기와 검색 헤더도 제한된 공간 안에서 스크롤할 수 있다.
- 전체 다운로드 목록에 가나다순, 제목/작가(도서) 또는 이름(글꼴) 검색, 도서 분류 필터를 적용한다. 서재 검색과 다운로드 검색은 별개다.
- 폴더블 힌지 회피, 3열 책 표지, 읽던 위치와 광고 동작은 기존 경로를 사용한다.

검증: 앱 코드·테스트 정적 분석 통과, Flutter 전체 129개 테스트 통과. 접힌 화면과 펼친 화면의 위젯 렌더 이미지를 확인했다. 신규 검사는 40개 이후 검색, 제목/작가+분류 조합, 탭별 검색어·스크롤 유지, 다운로드 중 탭 전환, 오류 재시도, 좁은 화면·큰 글자, 왼쪽 목록 독립 스크롤을 포함한다. Firebase 함수 단위 테스트 11개와 Quiz_Site TypeScript 검사도 통과했다. 실제 기기 및 운영 서버의 새 분류 필드 확인은 앱 업데이트와 서버·관리자 재배포 후 진행한다.
