# 쿠피리더 1.9.1 (20) 빌드와 출시 준비

작성: 2026-11-02. 최초 요청은 출시 파일 생성이었다. 이후 사용자가 대표 이미지만 교체하고 양쪽 스토어 게시까지 진행하도록 승인했다. 최신 업로드·심사 상태는 아래 후속 기록을 따른다. 서버 배포, Remote Config 변경, Git 커밋·푸시는 수행하지 않는다.

## 이번 빌드에 포함되는 내용

- 대량 책 가져오기를 앱 안의 작업 화면에서 진행하고 파일 받기·서재 등록·표지 연결 상태를 표시한다. 중단·실패 항목 재시도·작업 복구를 지원한다.
- 많은 책과 묶음책의 휴지통 삭제를 작은 단위로 처리하고 진행 상태를 표시한다.
- 묶음책 편집에서 전체 선택과 정렬을 제공한다.
- 공개 도서 목록을 캐시에서 먼저 표시하고 서버에서 갱신한다. 썸네일 중복 요청과 메모리 사용을 줄인다.
- 기존 한국어·영어·일본어 지원, 넓은 화면 독서·서재, 개인정보 기본 선택을 유지한다.

달력·독서 기록 페이지는 이번 빌드에 포함하지 않는다. `store-assets/2026-11-02-foldable-v2/`는 기기 목업 시안이다. 게시용 대표 이미지는 기존 SVG 조판에 각 언어의 실제 표지·본문 캡처를 넣어 `store-assets/2026-11-02-representative/`에 별도로 만들었다. 상세 스크린샷은 유지한다.

시스템 파일 선택창에서 Google Drive 폴더를 나열하는 지연까지 해결했다고 표현하지 않는다. 앱이 종료된 뒤 백그라운드 가져오기가 계속된다고 안내하지 않는다.

## 출시 전에 확인할 사항

- 기존 업로드 키·Apple 배포 서명을 유지한다. Android·iOS 각각 최종 빌드와 패키지 검증 결과를 아래에 기록한다.
- 실제 기기에서 대량 Drive 파일 선택·가져오기·중단·앱 재시작·재시도, 많은 책의 휴지통 삭제를 확인해야 한다. 자동 테스트와 빌드 성공은 실기기 검증 완료를 뜻하지 않는다.
- 공개 API 읽기 확인에서 `nextChangeAt` 필드가 아직 응답하지 않았다. 예약 공개 시각에 맞춘 캐시 만료와 새 관리자 페이지 API를 사용하려면 [서버 적용 순서](대량-가져오기와-목록-캐시-개선.md)를 따른다. 이 필드가 없어도 앱은 기존 목록을 읽고 60초 갱신 정책을 사용한다.
- 새 대표 이미지의 합성·언어별 내보내기·등록은 아래 기록과 같이 완료했다. 기존 상세 스크린샷은 유지했다.
- 스토어 승인·제공 중 버전과 번호 중복 여부는 업로드 직전에 확인한다.

## 검증 결과

- Flutter 출시 소스 정적 분석: 문제 없음. 테스트의 중괄호 스타일 두 곳을 정리했다.
- Flutter 전체 회귀 테스트: 386개 통과. 독서 마지막 화면·문장 선택 공유 스크립트 검사도 통과했다.
- Android 출시 AAB 빌드 성공. 패키지·버전·코드 일치, minSdk 24 / targetSdk 36, 디버그·테스트 전용 플래그 꺼짐을 확인했다.
- bundletool 1.18.1 유효성 검사, 기존 업로드 키로 서명된 콘텐츠 796개 검증, Readium 서비스 식별자 7개 보존 검사를 통과했다.
- arm64-v8a·x86_64의 네이티브 라이브러리 10개 ELF LOAD 정렬이 16KB 이상임을 확인했다. 16KB 실기기 실행 검증과는 구분한다.
- iOS 출시 아카이브와 App Store용 IPA 내보내기 성공. 최소 iOS 15.5, 한국어·영어·일본어, 운영 AdMob 앱 ID와 통계 기본 꺼짐을 확인했다.
- IPA ZIP 무결성, `codesign --verify --deep --strict`, 배포 프로비저닝 검증 통과. `get-task-allow=false`, 기존 Team·Bundle ID 일치를 확인했다.
- Android·iOS 모두 포함된 책 자산 13개가 저장소의 원본과 일치했다.
- 파일 크기와 SHA-256은 `work/release/1.9.1-20/checksums.json`에 기록했다.
- 빌드 단계에서 실기기 설치는 하지 않았다. 이후 사용자 요청에 따라 아래와 같이 스토어 업로드·심사 제출을 진행했다. 서버와 웹은 배포하지 않았다.
