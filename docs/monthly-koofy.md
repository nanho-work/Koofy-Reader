# 월간 쿠피 운영 및 구현

2026-10-25. 코드 구현 단계. 운영 서버 배포·앱 스토어 빌드/제출은 별도.

## 사용자 흐름

- 서재의 오늘의 쿠피: 언어별 최신 공개 월간호의 최신 발행 회차를 표시한다. 읽기를 누르면 미설치 회차를 받아 동일한 catalog book ID로 연다.
- 지난 이야기: 해당 월간호 회차 목록. 회차별 표지·발행 당일 새 이야기·읽기 진행 상태·직접 읽기.
- 받은 회차는 `group_monthly_{seriesId}` 서재 묶음에 모인다. 책 파일·네이티브 locator·책갈피 ID는 바꾸지 않는다. 사용자가 다른 묶음에 옮긴 책은 다시 가져오지 않는다.
- 합본 공개와 월간호 연결이 모두 완료되면 서버의 다운로드 목록에서 연재 대신 합본을 제공한다. 새 월간호가 등록되면 오늘의 글은 그 월간호에서 가져온다.
- 합본 안내는 연결 공개 시점부터 30일간 제공한다. 확인했어요는 해당 합본 ID의 안내만 이 기기에서 숨긴다. 합본 자체는 다운로드 목록에 계속 남는다.
- 기존 회차·기록은 자동 삭제하지 않는다. 합본은 별도 책이므로 회차의 책갈피/읽던 위치를 합본으로 자동 이식하지 않는다.
- 합본이 비공개/삭제되거나 조건을 충족하지 않으면 기존 연재의 목록 노출을 복구한다.

## 관리자 작업 순서 (Quiz_Site)

1. 월간 쿠피 → 월간호 · 회차에서 언어·제목·대표 표지·발행 월(예: 2026-11)을 지정해 공개한다. 언어별로 작품을 각각 만든다.
2. 회차별 EPUB 또는 TXT, 이미지, 제목, 발행일을 입력하고 공개한다. 예약 발행은 공개된 콘텐츠의 발행일을 기준으로 처리하므로 날짜 전에 미리 공개해도 된다.
3. 일괄 등록은 회차 번호를 그 월의 날짜로 사용한다(001 → 1일). 다른 일정이면 개별 회차에서 수정한다. 존재하지 않는 날짜는 서버가 거절한다.
4. 월말에 직접 제작한 합본 EPUB을 **월간 쿠피 → 완결 합본** 탭에서 등록한다. 같은 발행 월·언어를 지정하고 표지와 EPUB을 올려 공개한다.
5. 월간호 · 회차 탭에서 해당 월간호의 완결 합본 선택으로 방금 공개한 책을 연결한다. 완결 상태가 선택된다. **수정 내용 공개**를 눌러 전환한다.
6. 다음 월간호도 1번부터 등록한다. 앱이 빈 월간호를 자동 생성하거나 합본 EPUB을 자동 제작하지는 않는다.

발행 날짜는 한국 시간(Asia/Seoul) 기준. 앱 기기 시간을 변경해도 서버의 미래 회차 다운로드 제한은 유지된다. 한국어/영어/일본어는 기존 언어 필터를 사용하며, 지원하지 않는 기기 언어는 영어로 해석한다. 번역본이 없다고 다른 언어 회차를 대신 노출하지 않는다.

공개한 월간호의 발행 월·언어는 변경할 수 없다. 잘못 등록했다면 새 콘텐츠를 만들고 기존 콘텐츠의 공개 여부를 정리한다. 일반 연재를 월간호로 소급 전환하는 UI는 제공하지 않는다.

## 데이터와 API

- 기존 `readerContent` / 공개 스냅샷 사용. 새 컬렉션이나 로그인 없음.
- `issueMonth`: `YYYY-MM`, 빈 값이면 일반 콘텐츠.
- `releaseDate`: `YYYY-MM-DD`, 월간 회차 필수, 해당 월의 실제 날짜여야 함.
- `compilationId`: 연재에만 설정. 같은 월·언어의 공개된 단권 EPUB + 완결 상태 검증.
- 공개 스냅샷의 `compilationLinkedAt`: 안내 시작 시점. 동일 합본의 단순 재공개로 초기화하지 않음.
- `readerCatalog?action=monthly&language=ko|en|ja`: 현재 회차/부모 월간호 및 최근 연결 합본 반환.
- 기존 목록·회차 수·서명 다운로드 URL 발급에도 미래 발행일 제한 적용.
- 부모 연재를 비공개로 만들지 않고 유효 합본이 있을 때만 목록에서 숨김. ID로 조회하는 기존 회차 접근은 유지.
- 앱은 시작·복귀 및 포그라운드 5분 간격으로 월간 목록을 새로 확인. 네트워크 실패가 기존 오프라인 서재를 막지 않음.
- 다운로드 파일 검증 성공 후 묶음 저장 실패는 파일을 롤백하지 않음. 이 경우 받은 책은 일반 서재에 남으며 수동 묶음 정리 가능.

## EPUB 이미지 제작 규칙

현재 뷰어는 별도 표지를 본문 첫 칸에 넣는 준비 코드를 이미 가지고 있다. 본문에 출판사 표지 페이지가 있으면 중복 삽입을 피하므로, **회차 EPUB에 별도 표지 페이지를 넣지 않고 관리자 회차 표지를 지정**하는 구성이 가장 단순하다. 한 페이지 배치에서는 표지 다음 글, 두 페이지 배치에서는 첫 칸 표지 다음 칸 글로 흐른다. 연속 스크롤 모드는 페이지 고정 배치를 보장하지 않는다.

합본은 각 이야기를 별도 XHTML spine 항목으로 만들고, **동일 XHTML 안에서 이미지 다음 본문** 순서로 제작한다. 이미지와 본문을 서로 다른 spine 항목으로 나누면 두 페이지에서 맞은편 배치를 보장할 수 없다. 다음은 제작 시 참고할 CSS이며 실제 EPUB을 넣어 iOS/Android에서 최종 확인해야 한다.

```css
.story-image {
  width: 100%;
  height: calc(100vh - 2px);
  margin: 0;
  break-inside: avoid;
  -webkit-column-break-inside: avoid;
  break-after: column;
  -webkit-column-break-after: always;
}
.story-image img { width: 100%; height: 100%; object-fit: contain; }
```

합본은 현재 파일당 20MiB 제한을 지킨다. 28~31장의 이미지는 압축해 넣는다. 텍스트 1~2쪽은 제작 분량 기준이며 사용자의 글꼴·글자 크기에 따른 실제 페이지 수는 달라진다.

## 검증 및 배포 순서

1. Koofy-Reader Functions 배포. 새 서버는 기존 앱과 호환.
2. Quiz_Site 관리자 웹 배포(사용자가 커밋·푸시).
3. 앱 Android/iOS 업데이트 빌드·검증·배포.
4. 각 언어의 실제 회차/합본 파일로 스마트폰 1페이지·태블릿/폴더블 2페이지·스크롤 모드 확인.

서버 단위 테스트, Firebase 에뮬레이터 통합 테스트, Flutter 카탈로그/서재/표지 및 월간 위젯/묶음 테스트를 추가·실행한다. 실제 콘텐츠의 시뮬레이터/실기기 검수는 해당 파일 등록 후 필요하다. 전체 루트 정적 분석에는 `work/`의 과거 UI 스냅샷 오류가 있으므로 실제 앱 코드는 `flutter analyze lib`로 별도 확인한다.

관리자 메뉴 분리: 일반 도서·연재는 책·표지, 월간호·회차·합본은 월간 쿠피에서 관리한다. 이 메뉴 분리 자체는 웹만 배포하면 된다.
