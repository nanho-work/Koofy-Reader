# 실시간 화면 확인

일반 화면은 연결된 Android 실기기, 큰 화면은 Android 폴더블과 iPhone Duo 시뮬레이터로 확인합니다. 스토어 배포 작업과 별개입니다.

## 현재 구성

- 실기기: SM-G988N / R3CN20C3L5N. 기존 출시 서명으로 Debug 설치해서 책·설정을 유지했습니다.
- Android 폴더블: Koofy_Fold_Check / emulator-5554. 일반 폴더블 환경이며 특정 Galaxy 모델의 완전한 재현은 아닙니다. 처음 설치할 때 기존 에뮬레이터 앱과 서명이 달라 Flutter가 에뮬레이터 앱을 재설치했습니다.
- iPhone Duo: 94DD4CC3-4A4A-407F-A7CB-E60B991AD92F. Xcode 27.1의 DeviceHub에서 확인합니다. 접힘/펼침 상태는 창에서 선택합니다.

## 최초 준비 및 재실행

프로젝트 루트에서 실행합니다. 각 장치 실행 명령은 별도 터미널에서 유지합니다.

```sh
# 실제 기기의 앱을 삭제하지 않고 같은 서명으로 디버그 설치
KOOFY_DEBUG_RELEASE_SIGNING=true flutter run --debug -d R3CN20C3L5N --pid-file /tmp/koofy-live-phone.pid

# 폴더블 에뮬레이터를 먼저 켠 다음, 위에서 만든 APK 재사용
flutter run --debug -d emulator-5554 --use-application-binary build/app/outputs/flutter-apk/app-debug.apk --pid-file /tmp/koofy-live-fold.pid

# iOS는 별도 UI 미리보기 복사본 준비
python3 scripts/prepare_duo_preview.py
cd work/live-duo
flutter run --debug -d 94DD4CC3-4A4A-407F-A7CB-E60B991AD92F --pid-file /tmp/koofy-live-duo.pid
```

기기가 바뀌면 `flutter devices`로 ID를 확인합니다. 서명이 다른 기기에는 Flutter가 앱을 삭제하고 재설치할 수 있으므로, 기존 앱 데이터가 있는 기기의 서명을 먼저 확인해야 합니다.

## 파일 저장 후 자동 반영

프로젝트 루트의 별도 터미널에서:

```sh
python3 scripts/watch_ui_reload.py
```

`lib/**/*.dart` 변경을 감지해 약 1초 뒤 세 세션에 핫 리로드를 요청합니다. Duo의 별도 복사본에도 `lib`를 동기화합니다. 감시기는 Ctrl+C로 중지합니다. 앱을 강제 종료하거나 USB가 끊어지면 디버그 세션을 다시 실행해야 합니다.

- 화면 배치·색상·간격: 핫 리로드 대상.
- 초기화 로직·전역 상태 변경: 실행 터미널에서 `R`로 핫 리스타트.
- Swift/Kotlin 독서 뷰어, 플러그인, SDK, 일부 자산 변경: 다시 빌드해야 합니다. iOS 복사본은 다시 준비합니다.
- 실기기에 표시되는 디버그 성능을 출시 성능으로 해석하지 않습니다.

## Duo 미리보기 제한

현재 고정된 ML Kit 번역 SDK는 arm64 시뮬레이터 바이너리가 없습니다. 따라서 `work/live-duo`에만 번역 대체 구현을 넣습니다. 실제 프로젝트의 번역 구현과 의존성은 그대로입니다. 이 복사본은 절대 출시/아카이브에 사용하지 않습니다.

Flutter 3.35는 Pods의 `arm64e` 제외 설정을 `arm64` 제외로 잘못 판정합니다. 미리보기 Debug 설정에서만 이를 보정했습니다.

Duo 미리보기는 번역 검증에 사용할 수 없습니다. 광고·동의·TTS 등 기기 의존 동작은 실제 iPhone에서도 별도로 검증합니다.

2026-10-30: 세 대상의 VM 연결 및 수동 핫 리로드 성공을 확인했습니다.

### 실기기 자동 연결이 끊길 때

이번 실행에서는 자동 감지 대신 현재 프로세스가 출력한 VM 주소로 직접 연결했습니다. 예전 실행의 주소를 사용하지 않습니다. `adb logcat -d -s flutter:I`에서 현재 앱 PID의 `The Dart VM service is listening on` 주소를 확인한 뒤:

```sh
flutter attach -d R3CN20C3L5N --debug-url '기기 로그의 현재 VM 주소' --no-dds --no-devtools --pid-file /tmp/koofy-live-phone.pid
```

`--debug-url`에는 임의의 Mac 포워딩 포트가 아니라 기기 로그에 나온 주소를 전달합니다. Flutter가 전달 포트를 생성합니다. 이 주소는 앱 프로세스가 다시 시작될 때 바뀝니다.


## 문고 화면 크기 기준 (2026-10-30)

- 기기 이름이 아닌 Flutter 논리 화면 크기와 실제 책 영역 폭으로 열 수를 결정한다.
- 일반 세로 폰: 기본 3열, 좁은 화면이나 큰 글씨에서는 줄인다.
- 짧은 변 600 이상인 확장 화면: 가로/세로 비율 1.28 이상이면 기본 5열, 나머지는 기본 4열이다.
- 큰 태블릿: 가로형 폭 1200 이상은 6열, 세로형 폭 1000 이상은 5열이다.
- 분류 메뉴와 여백을 제외하고도 카드 최소 폭(글자 크기 반영)을 확보할 수 있어야 한다. 회전·분할 화면 시 다시 계산한다.
- 문고와 작품 안 회차 목록에 같은 계산을 사용한다.
- 공식 물리 해상도: iPhone Duo 내부 2670×1878, Fold8 내부 2448×1848, Fold8 Ultra 내부 2504×2256. 픽셀 해상도와 앱 논리 크기는 다르므로 이를 그대로 레이아웃 기준으로 쓰지 않는다.
- 현재 Duo 시뮬레이터 framebuffer는 2853×2007로 공식 물리 해상도와 차이가 있으며, Android `Koofy_Fold_Check`는 1768×2208 / 420dpi 범용 폴더블이다. 실제 Fold8 Ultra 검증으로 간주하지 않는다.
