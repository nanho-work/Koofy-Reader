# 서재 사용성과 데이터 보존 개선 (2026-09-27)

## 적용 범위

- 묶음 표지의 권수 배지와 더보기 버튼을 상단 한 줄에 배치한다. 버튼의 44×48 터치 영역은 유지하며 표지 열기 동작과 분리한다. 좁은 카드에서는 권수 문자열을 줄임표 대신 축소해 보여 준다.
- 로컬 TXT 가져오기에서 기존 Unicode 판독이 실패하면 CP949/EUC-KR 변환 결과를 먼저 확인한다. 확인 후 앱 소유 사본만 UTF-8로 저장하고 원본은 바꾸지 않는다. 거부한 파일은 실패와 구분해 건너뛴 수에 포함하며 나머지 가져오기는 계속한다.
- 같은 확장자와 같은 내용의 로컬 파일은 SHA-256으로 중복을 방지한다. 이름/선택 경로가 같아도 내용이 다르면 별도 책으로 추가하며 기존 본문을 유지한다. UTF-8과 CP949의 인코딩 차이가 있는 파일은 변환 후 바이트가 같을 때 중복으로 처리한다. Unicode 정규화나 줄바꿈 정규화까지 수행하는 의미 기반 중복 판별은 아니다.
- 책 삭제를 휴지통 이동으로 변경한다. 원본 사본, 표지, 독서 기록을 보존한다. 묶음 해제 시에도 묶음 정보와 표지를 보존한다. 휴지통에서 복원할 수 있고 자동 만료/영구 삭제는 하지 않는다. 제공 도서를 다시 다운로드한 경우에도 서재에 다시 표시한다.
- 백업에 독서 표지 표시, 음성 설정, 듣던 위치를 추가한다. 기존 백업도 읽을 수 있으며 복원 기기의 현재 값은 우선 보존한다. 백업 화면에서 최근 저장 시각과 30일 경과 안내를 제공한다.
- 설정의 진단 정보는 앱/OS 버전, 화면 크기, 보기 설정만 표시하고 사용자가 복사한다. 본문, 제목, 파일 경로, Locator, 광고 식별자와 음성 정보는 포함하지 않으며 서버 전송을 추가하지 않는다.

## 저장 형식과 경계

| 위치 | 내용 |
| --- | --- |
| `Book.sourceHash` | 선택 필드. 가져온 사본의 SHA-256. 이전 책은 필요한 경우 원본 스트림으로 계산하며 백업 복원은 검증된 본문으로 다시 계산한다. |
| `library_trash_v1` | 책/묶음 ID별 제목, UTC 삭제 시각, 종류 및 해제한 묶음의 스냅샷. 실제 책 파일은 지우지 않는다. |
| `library_last_export_at_v1` | 파일 선택기가 저장 성공을 반환한 마지막 백업 시각. 취소 시 갱신하지 않는다. |
| 백업 manifest `displayCover`, `speech` | 버전 1에 선택 필드로 추가. 없는 구형 백업은 기존 동작 유지. |
| `koofy_reader/maintenance` | 리더가 닫힌 상태에서만 `exportSpeech`/`mergeSpeech` 허용. |
| Android `reader_speech`, iOS `reader.speech.*` | 기존 듣기 설정 저장소를 그대로 사용. 기존 키가 있으면 복원으로 덮어쓰지 않는다. |

휴지통의 책은 일반 서재와 백업에서 제외한다. 복원하려는 묶음의 책이 이미 다른 묶음에 들어갔다면 현재 소속을 유지한다. 사용자가 그 사이 묶음을 재정렬/편집했다면 삭제 전 배치를 강제로 덮어쓰지 않는다. 묶음 해제 전에 복구 정보를 먼저 기록하므로 중간 실패 시에도 기존 묶음을 잃지 않으며 이미 존재하는 묶음을 중복 생성하지 않는다.

음성 백업은 속도·목소리 ID·따라가기와 백업에 포함된 책의 듣던 위치만 허용한다. Android와 iOS 사이에서는 목소리 ID를 적용하지 않으며 기기에 설치된 음성으로 다시 선택한다. 음성 파일, 취침 타이머, 다운로드 글꼴 파일, 광고 동의·보상, 휴지통은 백업 범위 밖이다.

네이티브 음성 저장소와 SQLite/환경설정은 하나의 트랜잭션이 아니다. 예외 발생 시 Dart 설정은 기존 롤백 절차로 복구하지만 프로세스 종료 시 신규 음성 키가 먼저 남을 수 있다. 기존 값은 덮어쓰지 않고 재복원은 멱등적으로 수행한다. OS 파일 선택기가 저장 성공으로 반환한 뒤의 클라우드 업로드 완료까지 보장하지 않는다.

## 한글 인코딩 테이블

`python3 tool/generate_cp949.py`로 Python 표준 CP949 매핑을 `assets/encoding/cp949.bin`에 생성한다. 외부 인코딩 패키지를 추가하지 않았다. 변환은 별도 isolate에서 수행하며 잘못된 바이트/불완전한 두 바이트 문자/바이너리 제어문자를 거부한다. 입력과 변환 결과 모두 기존 TXT 용량 한도 20 MiB를 적용한다. 유효한 CP949 바이트로도 엉뚱한 문자가 만들어질 수 있으므로 인코딩 자동 감지를 확정으로 취급하지 않고 사용자 미리보기 확인을 요구한다.

- Android API 36 에뮬레이터: `SpeechBackupChannelTest`와 표지→본문/TTS 시작 테스트 통과.
- iPad Air 11-inch (M3) 시뮬레이터: 음성 백업 현재 값 보존·타 OS 목소리 제외 및 표지/스크롤 왕복 테스트 통과.
- 실제 iPhone은 연결 불가 상태라 실기기 검증은 하지 못했다. 장시간 독서 성능이나 저장 공간 부족을 실기기에서 측정했다는 의미는 아니다.

## 실기기 확인 순서

1. 좁은 화면/펼침 화면에서 묶음 권수와 상단 오른쪽 더보기를 확인하고, 표지 탭이 묶음을 열고 메뉴 탭이 메뉴만 여는지 확인한다.
2. CP949·EUC-KR TXT를 여러 개 선택해 정상 변환/한 파일 건너뛰기/잘못된 파일 이후 계속 가져오기를 확인한다.
3. 책 삭제 및 묶음 해제 후 앱을 완전히 종료하고 다시 열어 휴지통 복원, 표지·읽던 위치·책갈피 보존을 확인한다.
4. 새 환경과 이미 읽던 환경 각각에 백업을 복원한다. 현재 기록은 유지하고 없는 기록만 추가되는지, 다른 OS에서는 음성을 다시 선택하는지 확인한다.
5. 기기 파일 앱/클라우드 위치에서 백업 저장·취소 후 마지막 저장 시각을 확인한다. 진단 정보를 직접 검토하고 복사한다.

## 되돌리기

이번 변경 파일 전체를 일괄 되돌리면 이전 미커밋 작업까지 손실될 수 있으므로 기능별 변경만 분리해 되돌린다. 기존 본문/독서 DB를 삭제하거나 초기화하지 않는다. 새 JSON 필드는 선택 사항이다. 구버전 앱은 휴지통 필터를 이해하지 못해 삭제했던 책이 다시 보일 수 있으나 파일과 기록은 유지된다. 새 CP949 변환본은 UTF-8이므로 이전 리더에서도 읽을 수 있다. 휴지통 JSON과 듣기 설정을 정리하거나 버전 번호를 낮추는 마이그레이션은 필요하지 않다.

배포, 스토어 업로드, 앱 버전 변경은 이번 작업에 포함하지 않았다.
