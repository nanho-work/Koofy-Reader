# 독서 기록 달력과 시간 집계

## 이번 작업 범위

하단 메뉴는 홈·도서·서재·기록·설정이다. 앱을 새로 실행하면 이전 선택 대신 홈으로 시작한다. 이번 작업은 다음 업데이트용 소스 패치이며 스토어 제출·커밋·푸시는 하지 않는다. 기존 1.9.1(20) 제출 파일을 덮어쓰지 않는다.

## 이용 흐름

- 기록의 기본 화면은 한 달 달력이다. 연·월은 가운데, 그래프 전환 아이콘은 오른쪽에 둔다.
- 첫 기록이 있는 달부터 다음 달까지만 이동한다. 중간에 기록이 없는 달은 지나갈 수 있으며, 기록 없는 날짜는 눌러도 상세로 이동하지 않는다.
- 읽은 날에는 기존 쿠피 스티커의 캐릭터 부분과 그날 합산 시간을 표시한다. 표시 예: 41분 / 1시간 20분 / 1분 미만. 초까지의 정밀값은 내부에 보존한다.
- 날짜를 누르면 그날 읽은 책의 표지·제목·책별 독서 시간이 나온다. 서재와 같은 표지·그리드 너비 기준을 사용하며, 검색·추가·삭제 기능은 넣지 않는다.
- 묶음책은 묶음 표지·제목으로 모으고 회차별 내역을 펼쳐 볼 수 있다. 책을 삭제해도 기록용 작은 표지 사본과 제목은 남는다.
- 그래프에는 일별·월별만 제공한다. 일별은 선택한 달의 날짜별, 월별은 해당 연도의 월별 합계다. 기록 없는 날은 0이다. 확대·축소·전체 보기, 핀치 확대와 이동, 지점 선택을 제공한다. 월별 지점을 누르면 그 달 일별 그래프로 이동한다.
- 한·영·일 날짜와 시간 문구를 지원한다. 이미지의 한국어 문구는 UI에서 잘라 캐릭터만 공통 표시한다.

## 시간 집계 기준

실제 독서 여부를 판정하지 않고, 준비 완료된 뷰어가 화면에 활성 상태로 보인 시간을 기록한다. 네트워크/Analytics 동의와 관계없는 기기 내 기능이다. 이전 누적 평가 요청 시간은 날짜·책 구분이 없으므로 가져오지 않는다.

- Android: Activity pause/resume 및 window focus 신호를 사용한다. 설정·목차 등 대화상자 또는 다른 화면에 가려지면 중단한다.
- iOS: scene 활성/비활성 신호를 사용한다. 추가로 0.5초 간격으로 모달·화면 표시 상태를 확인해 가려진 시간을 제외한다. 이 폴링 경계에는 최대 약 0.5초의 오차가 있다.
- 배경 TTS 이용 시간은 집계하지 않는다. 포그라운드 뷰어 안에서 듣는 시간은 집계한다.
- 15초마다 저장하며 일시정지·종료 시 즉시 반영한다. 강제 종료 시 마지막 미저장 구간(통상 최대 약 15초)은 남지 않을 수 있다. 저장 공간 오류에도 독서는 막지 않고 기존 오류 경로로 알린다.
- 자정에 걸친 구간은 기기 현지 날짜별로 나눈다. 경과 시간은 Stopwatch를 사용한다.

## 구조와 백업

- `lib/features/reading_diary/data/reading_diary.dart`: 날짜별 직렬 저장, 표지 축소 스냅샷, 날짜 분리와 백업 병합.
- `lib/features/reading_diary/presentation/`: 달력·날짜 상세·라인그래프·시간 표기.
- `NativeReaderCoordinator`: 기존 네이티브 이벤트와 공통 시간 집계 연결. 복구된 과거 체크포인트는 새 시간으로 추가하지 않는다.
- `NativeReaderLaunchPage`: 실제 책 또는 소속 묶음책의 표시 메타데이터를 전달.
- 저장 키: `reading_diary_v1_YYYY-MM-DD`. LocalStorage에만 저장한다. 읽은 기록은 메모리에 캐시하고 변경된 날짜만 갱신하며 백업 복원 시 캐시를 비운다.
- 서재 ZIP 백업에 포함한다. 반복되는 기록 표지는 해시 기준으로 payload를 재사용한다. 복원은 같은 날짜·책의 최대 시간을 유지해 동일 백업을 여러 번 복원해도 중복 합산하지 않는다. 옛 백업에 기록 항목이 없어도 복원한다. 서로 다른 기기에서 같은 날 읽은 시간의 완전한 합산·동기화 기능은 아니다.
- 앱 내 개인정보 안내 3개 언어에 로컬 독서 기록·표지 보존을 추가했다. 웹 개인정보 안내의 동일 문구 반영은 다음 출시 전 확인할 사항이다.

## 검증

- 전체 Flutter 테스트 400개 통과: 날짜 분리·직렬 쓰기·반복 백업 병합·가려진 뷰어/백그라운드 제외·기본 홈 진입 포함.
- 한국어·영어·일본어, 320×700 / 840×700 / 1200×900 논리 크기에서 달력·상세·그래프 위젯 검사 및 렌더 캡처.
- 테스트 예시 화면: `work/diary-preview/`. 미리보기 데이터는 테스트에서만 생성하며 실제 앱에 샘플 기록을 삽입하지 않는다.
- Android debug APK 빌드 성공: `build/app/outputs/flutter-apk/app-debug.apk`.
- iOS simulator debug 빌드 성공: `build/ios/iphonesimulator/Runner.app`.
- 두 플랫폼 네이티브 코드 컴파일 검증까지 완료했다. 이번 작업에서 실기기 설치·잠금/광고 모달 중 실제 시간 계측은 하지 않았으며 다음 확인 항목이다.
- 최종 테스트·분석·네이티브 빌드 로그는 `work/diary-verification/`에 보관한다.

## 2026-11-02 시뮬레이터 실행 확인

- Android `Koofy_Fold_Check`를 부팅하고 기존 서명과 맞추기 위해 `KOOFY_DEBUG_RELEASE_SIGNING=true flutter build apk --debug --no-pub`로 만든 APK를 덮어 설치했다. 기존 데이터는 삭제하지 않았다. 홈 화면의 5개 메뉴(기록 포함) 실행을 확인했다.
- iPhone Duo(iOS 27.1)는 새 Xcode의 **Device Hub** 앱에서 열었다. 기본 Flutter 시뮬레이터 빌드는 x86_64이므로 해당 arm64 기기에 설치되지 않았다. arm64로 다시 빌드하면 기존 MLKitCommon의 iOS 실기기용 바이너리 링크 오류가 발생한다. 현재 의존성으로는 듀오에 이번 최신 앱을 실행하지 못했으며, 열린 기존 앱과 최신 기록 기능 검증을 혼동하지 않는다.
- 앞선 iOS 시뮬레이터 빌드 성공은 x86_64 컴파일 검증이다. 듀오 arm64 실행 또는 iOS 실기기 확인을 뜻하지 않는다. 시뮬레이터 제약을 피하기 위해 배포용 번역 기능·의존성을 이번 요청에서 변경하지 않았다.

## 2026-11-03 기록 화면 디자인 정리

- 공통 `DiaryStyle`과 `DiaryToolButton`으로 글자색·보조색·도구 크기·애니메이션 시간을 묶었다. 내용 최대 너비는 1040이며, 스티커는 최대 88×66 범위에서 조절한다.
- 월 제목은 연도 12 / 월 26의 위계로 나누고, 월 이동과 그래프 전환 버튼은 최소 44의 터치 영역을 유지한다. 오늘은 날짜 숫자의 원, 선택한 날은 얇은 테두리로 구분한다.
- 달력 구분선을 줄이고 쿠피와 시간을 가까이 묶었다. 일반적인 글자 크기에서는 한 달 전체를 배치하며 큰 글씨·짧은 창에서는 스크롤을 허용한다. 화면 전환은 180ms이며 동작 줄이기 설정을 존중한다.
- 날짜 상세는 하루 총시간을 먼저 보여주고 책 제목·책별 시간을 일관된 간격으로 맞췄다.
- 그래프 기간 선택과 확대 도구를 정리하고, 시간축 간격을 규칙적으로 맞췄다. 지점 탭 또는 길게 누른 뒤 이동으로 선 위의 시간 말풍선을 확인한다. 핀치 확대·이동도 유지한다.
- 집계·로컬 저장·광고·동의·네이티브 SDK 흐름은 이번 디자인 작업에서 변경하지 않았다. iOS와 Android가 같은 Flutter UI를 사용한다.
- 기록 화면 테스트 12개 통과(3개 언어×3개 크기, 큰 글씨·짧은 창 2개, 빈 기록), 기존 하단 메뉴 화면 검사 13개 통과. 정적 분석 문제 없음. 예시 데이터 캡처는 `work/diary-design-preview/`다.
- 이번 디자인 변경은 시뮬레이터나 실기기에 다시 설치하지 않았다. Android 에뮬레이터 연결이 없었고, iOS Duo 실행 제한은 위 기록대로 남아 있다. 커밋·푸시·스토어 제출은 하지 않았다.
