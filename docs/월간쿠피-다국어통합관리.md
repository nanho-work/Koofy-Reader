# 월간 쿠피 다국어 통합 관리

2026-10-29 변경. 앱의 저장 구조와 기존 콘텐츠 ID는 유지하고 관리자만 월·회차 단위로 묶었습니다.

## 사용하는 순서

1. 관리자 → 월간 쿠피에서 발행 연·월을 고르고 **3개 언어 월간호 만들기**를 누릅니다.
2. 한국어·영어·일본어 제목, 발행자, 이용조건이 자동 입력됩니다. 같은 월·언어가 이미 있으면 원래 항목을 유지하고 없는 언어만 만듭니다. 원고나 이미지를 자동 번역하지는 않습니다.
3. **월간호 설정**에서 표지를 넣고 **설정 저장**을 누릅니다. 공통 표지 하나 또는 언어별 표지를 사용할 수 있습니다. 언어별 파일이 우선합니다.
4. **회차 관리**에서 회차를 선택하고 한 화면의 세 언어 칸에 제목, 선택 글쓴이, TXT/EPUB, 이미지를 넣습니다. 공통 이미지 또는 언어별 이미지를 사용할 수 있습니다.
5. 저장할 언어를 체크합니다. **초안 저장**은 앱에 새 회차를 공개하지 않습니다. **선택 언어 공개·예약**은 과거/현재 일시이면 즉시, 미래 일시이면 지정 시각부터 노출합니다. 공개 일시는 한국 시간이며 해당 월 안이어야 합니다.
6. 첫 회차가 실제 공개되기 전에는 빈 월간호가 앱에 보이지 않습니다. 한국어만 준비되었다면 한국어만 공개할 수 있습니다.

## 기존 자료와 오류 처리

- 기존 월간호·회차·파일·공개 상태를 일괄 변경하거나 삭제하는 마이그레이션은 없습니다.
- 기존 월간호 제목도 생성 작업으로 덮어쓰지 않습니다. 제목 자동 채우기를 누르면 표준 제목으로 바꿀 수 있습니다.
- 같은 월·회차 번호를 번역본으로 묶어 표시합니다. 서로 대응하지 않는 기존 번호는 기존 개별 관리에서 확인합니다.
- 동일 월·언어가 중복된 경우 자동 병합하지 않고 안내합니다.
- 언어별 저장은 순차 처리합니다. 일부 실패 시 성공한 언어는 유지되고 실패한 언어만 재시도할 수 있습니다.
- 생성 재시도로 같은 월간호나 회차가 중복되지 않도록 서버 트랜잭션을 사용합니다.
- 기존 개별 관리에서 삭제, 비공개, 합본 관련 관리 등 종전 기능을 계속 사용할 수 있습니다.
- TXT는 기존 이미지 첫 페이지 EPUB 생성 경로를 그대로 사용합니다. 월말 합본도 기존 언어별 자동 합본 설정을 유지합니다. 완료된 합본 재생성 기능은 이번 변경에 포함하지 않습니다.

## 배포 순서 — 직접 실행

먼저 Koofy-Reader 폴더에서 서버를 배포합니다.

```sh
cd /Users/choenamho/Documents/GitHub/Koofy-Reader
firebase deploy --only functions:reader --project koofy-reader
```

firebase.json의 predeploy가 TypeScript 빌드를 수행합니다. 새 관리자 API가 있으므로 서버를 먼저 배포해야 합니다.

이번 변경으로 앱 바이너리를 새로 빌드할 필요는 없습니다. 운영 콘텐츠를 새로 생성하거나 변경한 작업은 없으며, 검증에는 demo Firebase 에뮬레이터를 사용합니다.

## 회차 일괄등록 (2026-10-30)

- 월간호 선택 → **회차 일괄등록** → 한국어 / English / 日本語 탭을 선택합니다.
- TXT·EPUB와 이미지를 여러 개 선택하거나 끌어다 놓습니다. 앞의 회차 번호가 같으면 연결합니다. 예: `1화_제목.txt` + `1화_그림.png`, `第1話_題名.txt`, `Episode 1_Title.txt`.
- 언어 탭을 바꿔도 선택한 파일은 유지됩니다. 저장 버튼은 현재 탭의 언어만 처리합니다.
- 같은 번호의 다른 언어 회차에 공개 일시가 있으면 가져옵니다. 언어마다 일시가 서로 다르면 자동으로 정하지 않으며 직접 확인합니다.
- 시작 일시와 발행 간격을 정한 뒤 **미저장 회차에 일정 적용**으로 일괄 배정할 수 있습니다. 각 행에서 수정할 수도 있습니다.
- 기존 회차는 ‘이미 등록된 회차’로 제외하며 덮어쓰지 않습니다. 중복 파일, 본문 누락, 이미지 누락(TXT), 월 밖의 공개 일시는 표시하고 건너뜁니다.
- 초안 저장 후 같은 화면에서 예약·공개로 이어갈 수 있습니다. 일부 실패 시 성공한 회차는 유지하고 실패한 행을 재시도합니다. 작업을 시작한 행의 수정은 개별 편집에서 합니다.
- 이번 일괄등록 추가는 Quiz_Site 웹 변경입니다. 앞선 다국어 서버 패치가 이미 배포되어 있으면 추가 서버/앱 배포는 필요 없습니다.
