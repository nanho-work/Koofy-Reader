# 대량 가져오기와 목록 캐시 개선

2026-11-01. 앱과 관리자, Firebase Functions를 함께 수정했다. 커밋·푸시·기기 설치·스토어 배포는 수행하지 않는다.

## 사용자가 보게 되는 변화

- 책 추가를 누르면 가져오기 화면이 열린다. 시스템 파일 선택창에서는 여러 원고와 표지를 함께 선택할 수 있다.
- 선택한 파일의 정보부터 가져온다. 모든 파일을 먼저 내려받은 뒤 앱으로 돌아오던 방식 대신, 앱 안에서 파일을 하나씩 받아 진행 상태를 표시한다.
- 시작 전에 개별 보관·새 묶음·기존 묶음 추가 및 표지 자동 연결을 선택한다. 가져오기 후 묶음·표지 팝업을 연속으로 기다리지 않는다.
- 파일 받는 단계, 파일명·받은 용량, 서재 등록 완료 권수, 표지 연결·묶음 정리 단계를 표시한다.
- 다른 화면으로 이동해도 앱이 살아 있는 동안 작업은 유지된다. 서재의 진행 버튼에서 작업 화면으로 돌아온다. 앱을 종료하면 다음 실행에서 기록을 읽고 사용자가 남은 작업을 재시도할 수 있다. 앱 종료 후 백그라운드 작업을 계속 보장하는 기능은 아니다.
- 중단은 진행 중인 파일 읽기 또는 안전한 등록 묶음이 끝나는 시점에 반영된다. 클라우드 공급자가 응답하지 않으면 90초 후 대기열을 멈춘다. 취소 중인 이전 요청이 남아 있을 때도 후속 파일 전체를 실패로 처리하지 않는다.
- 실패한 파일만 다시 시도하며 이미 등록된 책은 중복 생성하지 않는다. 완료된 임시 사본은 정리하되 서재 원본·표지·읽기 기록은 유지한다.
- 휴지통은 앞선 패치의 16개 단위 삭제·진행 표시·재시도를 유지한다. 묶음 편집의 전체 선택·정렬도 유지한다.

## 데이터와 구현 기준

- iOS: `koofy_reader/book_import` 채널, 복사하지 않는 UIDocumentPicker와 보안 북마크, 보안 접근 범위 내 NSFileCoordinator 읽기. 읽기는 별도 큐에서 수행한다.
- Android: 같은 채널, ACTION_OPEN_DOCUMENT 및 유지 가능한 URI 읽기 권한, 별도 실행기의 스트리밍 복사. 원본 문서를 변경하거나 삭제하지 않는다.
- 공급자가 장기 접근 권한을 지원하지 않거나 클라우드 파일이 이동·삭제되면 재선택이 필요할 수 있다.
- 원고 16개마다 서재 인덱스를 한 번 저장한다. 등록 확정 후에만 진행 기록에 완료를 표시한다. 재시도 시 파일 해시로 이미 가져온 책을 확인한다.
- 표지도 16개마다 서재와 유효한 책 ID를 한 번 조회한다. 파일명 중복·모호한 연결은 자동 적용하지 않으며 기존 개인 표지는 유지한다.
- 가져오기 작업은 ChangeNotifierProvider에서 관리하고 `library_import_job_v1`에 진행 기록을 저장한다. 그룹 ID도 기록해 재시작 시 중복 묶음을 방지한다.
- 임시 파일 삭제는 시스템 캐시의 `koofy_import` 하위 경로인지 확인한 후에만 수행한다.

## 앱 도서 목록

- 서버 주소·언어·목록 종류별 완성된 공개 메타데이터를 기기 캐시에 저장한다. 관리자 초안과 서명 URL은 저장하지 않는다.
- 캐시가 있으면 먼저 보여주고, 60초가 지났거나 예약 공개 시각이 도달하면 갱신한다. 사용자가 직접 새로고침하면 유효 시간과 관계없이 서버를 확인한다.
- 최초 조회에는 첫 페이지부터 보여주고 나머지 페이지를 이어 받는다. 전체 검색 인덱스를 다 받기 전에는 로딩 상태를 구분한다.
- 갱신 실패 시 이전의 완성된 목록을 유지한다. 부분적으로 받은 목록으로 정상 캐시를 덮어쓰지 않는다.
- 썸네일은 기존 디스크 파일 검증을 유지하면서 진행 중 요청을 합치고, 메모리에서는 최대 32개·8MB로 제한한다. 다운로드 상태 확인도 목록 전체 기준으로 한 번씩 읽는다.
- 다운로드 실행 시에는 기존대로 최신 게시 상태·파일 버전·해시를 확인한다. 목록 캐시가 배포 권한 검사를 대체하지 않는다.

## 관리자와 서버

관리자 코드는 별도 저장소 `/Users/choenamho/Documents/GitHub/Quiz_Site`에 있다.

- 일반도서·일반소설·연재소설·월간호 목록은 공통 페이지 조회 훅과 목록 컴포넌트를 사용한다. 연결된 번역본은 한 작품 안에 함께 포함한다. 기존 월간호는 월 기준으로 세 언어를 함께 조회한다.
- 처음부터 전체 자료를 기다리지 않고 필요한 페이지를 가져온다. 검색 시에는 뒤 페이지도 확인한다. 목록 위치와 더 보기 범위를 기억한다.
- 관리자 캐시는 메모리에서만 30초 유지하며 계정·서버 주소를 키에 포함한다. 계정 변경·권한 오류 시 지운다.
- 수정·등록·삭제 후 캐시를 무효화한다. 늦게 도착한 이전 응답이 새 캐시를 덮지 않도록 세대 번호를 확인한다. 새로 만든 작품도 목록 첫 페이지 밖에 있다는 이유로 사라지지 않도록 반영한다.
- 편집 화면을 열 때는 작품과 번역본을 서버에서 새로 가져온다. 관리자 캐시를 최신 편집 데이터로 간주하지 않는다.
- 서버의 공개 목록은 작품마다 회차 수를 따로 조회하는 대신 최대 30개 작품을 묶어 회차 정보를 조회한다. 예약 공개는 게시된 스냅샷의 언어·날짜·시각 기준으로 판단한다.
- 서버 응답의 `nextChangeAt`은 예약 공개·월 시작에 맞춘 앱 캐시 만료에 사용한다. 수동 새로고침과 별개다.
- 기존 관리자 API는 유지하고 페이지 API `action=works`, 최신 작품 API `action=work`를 추가했다. 인증·관리자 권한 검사는 그대로 적용한다.

## 적용 순서

이 문서는 실행 안내이며 아래 배포는 아직 수행하지 않았다.

1. Firebase 인덱스를 배포하고 생성 완료를 확인한다.

```sh
cd /Users/choenamho/Documents/GitHub/Koofy-Reader
firebase deploy --only firestore:indexes --project koofy-reader
```

2. Functions를 배포한다. 프로젝트의 predeploy가 TypeScript 빌드를 실행한다.

```sh
firebase deploy --only functions:reader --project koofy-reader
```

3. 사용자가 Quiz_Site 변경을 커밋·푸시해 관리자 웹을 배포한다. 새 관리자 API가 먼저 배포되어 있어야 한다.
4. 앱 변경은 iOS·Android 모두 재빌드가 필요하다. 먼저 실제 기기에서 대량 파일 선택·중단·재시작을 확인하고 스토어 반영 여부를 별도로 결정한다.
