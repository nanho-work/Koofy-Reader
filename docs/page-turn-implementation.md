# 페이지 전환 효과 구현

상태: 2026-09-20 구현 완료. Android 에뮬레이터·iOS 시뮬레이터 검증 완료.
실기기 성능·접힘 전환·iOS의 실제 왕복 드래그 취소 검증은 별도로 남는다.

## 사용자 동작

보기 설정의 **페이지 전환 효과**에서 `바로 넘기기` 또는 `책장 넘기기`를 선택한다.
기본값은 바로 넘기기이며, 현재 독서 설정의 저장 범위에 맞춰 책별로 저장한다.
연속 스크롤에서는 전환 효과를 적용하지 않고 선택값은 유지한다.
효과 설정만 변경할 때는 본문을 다시 나누지 않는다.

책장 넘기기는 실제 본문 이미지를 앞뒤로 사용하며, 넘김 완료 후 실제 Readium 본문으로 이어진다.
멈춰 읽을 때는 원래 본문을 사용한다. 단면에서는 한 화면, 펼침에서는 한 펼침씩 진행한다.
페이지 이미지가 아직 준비되지 않았다면 그 동작은 바로 넘기기로 처리한다.
진행 중인 책장 효과를 중간에 다른 효과로 바꾸지 않는다.

## 공통 계약과 저장

`pigeons/reader_api.dart`의 ReaderPreferences에 nullable 문자열 `pageTurnStyle`을 추가했다.
허용값은 `instant`와 `curl`이며, 누락/null은 이전 기록과 호환되도록 `instant`로 읽는다.

Dart/Kotlin/Swift 브리지 코드는 같은 Pigeon 버전으로 함께 생성한다.
Flutter DB의 preferences_json 및 네이티브 복구 저널에서 이 값을 보존한다.
DB 테이블 구조는 바뀌지 않는다. 전환 설정 변경 이벤트는 기존 정확한 본문 Locator를 유지한다.
기존 session generation, event sequence, DB commit 이후 ACK 규칙을 그대로 사용한다.

## 구현 경계

- Flutter: 설정 전달과 저장·복구. 페이지 이미지는 Flutter 채널을 오가지 않는다.
- Native provider: 주 독서 세션과 별도의 Readium 렌더링 문맥에서 주변 페이지를 준비한다.
- Native controller: 탭·드래그·완료·취소와 실제 본문 이동을 연결한다.
- Renderer: 실제 글씨가 담긴 앞면·뒷면으로 책장 효과를 표시한다.

준비용 뷰는 실제 본문과 같은 크기·레이아웃 설정을 사용한다.
폰트/이미지 로딩 및 레이아웃 안정화를 확인하고, 원본 화면과 준비 화면의 위치가 일치해야 사용한다.
미리보기는 실제 독서 기록을 쓰지 않는다. 변경된 레이아웃의 예전 이미지·콜백은 폐기한다.
정확한 문자 앵커와 함께 Readium의 읽기 진행률·위치 메타데이터도 유지한다.
iOS는 현재 DOM의 스크롤 진행률과 Readium Locator의 장·진행률이 일치한 뒤 메타데이터를 사용한다.

## 플랫폼별 구현

### Android

`ReaderPageSurfaces`가 부착된 별도 Readium navigator에서 실제 주변 화면을 준비한다.
폰트·그림 로딩과 레이아웃 안정화를 확인한 뒤 WebView의 visual-state callback을 기다리고
네이티브 Bitmap으로 캡처한다. 준비가 끝나면 미리보기 WebView를 해제한다.

`ReaderTurnHost`가 가로 드래그를 맡고, `ReaderPageTurns`가 준비·드래그·복귀·이동 확정을 관리한다.
바깥쪽 위·아래 모퉁이는 누르는 순간부터 책장 동작을 소유해 길게 잡고 이동할 수 있다.
그 밖의 본문에서는 기존 텍스트 선택과 링크를 유지한다.
`ReaderPageCurlView`는 원통형 곡면의 앞면·뒷면 삼각형을 구분하여 BitmapShader로 그린다.
손가락의 가로 이동은 넘김 진행률에, 세로 위치는 접히는 방향에 반영한다.
Android 10 이상에서는 하드웨어 Canvas를 사용하며, 이전 버전은 효과 레이어만 소프트웨어로 그린다.

이미지 한 장의 상한은 4,194,304픽셀이다. 현재·이전·다음 세 장은 최대 약 48MiB,
펼침 앞뒤 면을 잘라 만든 이미지까지 포함하면 최대 약 64MiB의 CPU Bitmap 공간이 필요하다.
이는 앱 전체 메모리 상한이 아니다. WebView, 캡처 중 임시 이미지, GPU 자원은 별도다.

### iOS

`ReaderPageFrameProvider`가 주 navigator와 같은 크기의 독립 Readium navigator를 준비한다.
부착된 WKWebView의 로딩·레이아웃 안정성과 실제 본문 위치를 확인하고 `takeSnapshot`으로 캡처한다.
미리보기 navigator는 작업 종료 시 해제한다. 내부 필드에 KVC나 리플렉션으로 접근하지 않는다.

`ReaderPageTurnController`는 UIKit의 `UIPageViewController.pageCurl`과 양면 페이지를 사용한다.
펼침에서는 전체 두 열 화면을 캡처한 뒤 좌우 면으로 나누며, 별도 반쪽 WebView로 재페이지네이션하지 않는다.
본문 중앙의 텍스트 선택과 가장자리 책장 제스처를 분리한다.
동작 줄이기 또는 VoiceOver가 활성화되어 있으면 바로 넘기기를 사용한다.

이미지는 한 화면당 약 250만 픽셀·배율 2 이내로 제한한다.
세 화면의 CPU 이미지 예산은 약 30MiB이며, UIKit의 전환용 복사본과 WebView 메모리는 별도다.

### 양면과 단면의 차이

펼침에서는 현재 오른쪽 면의 뒷면에 다음 펼침의 왼쪽 본문을 표시한다(LTR 기준).
단면에서는 뒷면과 아래에 드러나는 면이 같은 다음 본문을 보여주는 연출이다.
단면에서 양면이 보인다는 이유로 두 화면을 건너뛰지 않는다.
두 플랫폼은 서로 다른 네이티브 렌더러를 사용하므로 곡률·그림자가 픽셀 단위로 같지는 않다.

## 무효화와 실패 처리

글자 크기·테마·열 배치·화면 크기 변경은 준비 중인 이미지와 완료 콜백을 무효화하고 새 화면을 준비한다.
백그라운드 이동과 메모리 경고에서도 전환 자원을 정리한다.
자료가 준비되지 않았거나 실제 본문과 일치함을 확인할 수 없으면 해당 입력은 바로 넘기기로 처리한다.
이미지를 기다리느라 책을 읽기 시작하거나 페이지를 넘기는 동작을 막지 않는다.
iOS에서는 글자가 전혀 없어 정확한 문자 위치를 확인할 수 없는 화면도 이 기본 전환 경로를 사용한다.

이미지 캐시는 현재 독서 세션과 레이아웃 세대에 한정되며 디스크에 저장하지 않는다.
Readium 버전을 올릴 때는 공개 UIView/WebView 트리 탐색이 여전히 실제 화면 하나를 식별하는지 재검증한다.
이번 패치는 기존 지원 범위인 비보호 리플로우 EPUB을 대상으로 한다.
PDF·고정 레이아웃·DRM 지원을 추가하지 않는다.

## 검증 기록

- Flutter 전체 테스트 83개 통과 및 정적 분석 오류 없음.
- 저장소·코디네이터 테스트 19개 통과. 구버전 DB 설정, nullable 기본값, Pigeon codec,
  전환 설정의 저장·복구, 늦은 이전 세션 이벤트 거부, 정확한 문자 위치 보존을 포함한다.
- Android 네이티브 테스트 17개 통과(실패·건너뜀 0). 실제 EPUB의 이미지와 터치 이벤트를 사용했다.
  취소·앞뒤 이동·650ms 모퉁이 누르기·코너 탭 1회 이동, 긴 문단의 펼침 및 장 경계에서
  일반 Readium 이동 1회와 정확한 본문 위치가 일치하는지 확인했다.
  기존 읽기 복원·테마·저널 테스트와 글자 크기 변경에 따른 이미지 무효화도 포함한다.
- Android 단면·펼침·역방향 전환 중간 이미지를 확인했고, 초기 곡면의 줄별 깨짐을 수정했다.
- Android 앱 debug APK 빌드 성공.
- iOS 네이티브 자동 테스트 9개 통과, 실패 0. 실제 EPUB 이미지, UIKit 양면 구성,
  취소 delegate와 체크포인트 불변, 효과만 변경할 때 navigator 유지, 글자 크기·단면 변경,
  단면 앞뒤 이동, 일반 Readium 1회 이동과 장 경계의 위치 일치를 검증했다.
  기존 읽기 복원·설정·저널 테스트를 포함한다.
- 별도 수동 프로브로 iPad Simulator의 실제 드래그 완료를 단면·펼침 각각 확인했다.
  단면 프로브는 테스트 성공과 목표 Locator 일치를 확인했고, 전환 중간 녹화에서도
  다음 본문이 종이 뒷면에 올바르게 표시됨을 확인했다.
  실제 손가락 입력에 해당하는 취소 제스처는 사용한 UI 도구가 왕복 드래그를 지원하지 않아
  아직 확인하지 못했다. 자동 delegate 취소 테스트와 구분한다.
- 수동 드래그 프로브는 일반 테스트에서는 건너뛴다. 실행할 때만 별도 환경변수로 켠다.
- iOS 진행률 보존 및 이동 완료 상태 확인 보완 후 핵심 테스트 2개를 다시 실행해 통과했다.
  전체 테스트 9개와 중복되는 테스트이며 개수를 합산하지 않는다.
- iOS Simulator용 앱 빌드 성공. 서명된 실기기·배포용 iOS 빌드는 이번 검증에 포함하지 않았다.

검증 환경은 Android API 36의 작업용 에뮬레이터(1600×2200)와 iOS 26.3 계열 iPad Simulator였다.
테스트용 기기는 검증 후 종료·삭제했으며 사용자 기기의 앱이나 서재 데이터는 변경하지 않았다.

## 로컬 기기 확인

앱을 종료한 뒤 프로젝트에서 `flutter run -d <기기 ID>`로 다시 빌드해 설치한다.
보기 설정에서 책장 넘기기를 켜고 아래 동작을 확인한다.

1. 오른쪽 아래 모퉁이를 잡고 왼쪽으로 이동해 한 화면 넘기기.
2. 넘기던 손가락을 시작점으로 되돌리고 놓아 취소한 뒤, 서재에서 다시 이어 읽기.
3. 왼쪽 가장자리에서 이전 화면으로 이동하고 글자 크기 변경 후 같은 문장 확인.
4. 단면·펼침 변경 및 접기·펼치기를 반복한 뒤 이어 읽기 확인.
5. 배경색 변경, 연속 스크롤 전환, 빠른 연속 넘김과 앱 백그라운드 복귀 확인.

이미지가 아직 준비되지 않은 입력은 바로 넘기기로 처리한다. 로딩을 기다리는 화면은 추가하지 않는다.
실기기의 프레임 시간·최대 메모리·발열·전력, 특히 Android 24–28의 소프트웨어 효과 렌더링은 별도 측정 대상이다.

## 유지보수

전환 설정이나 프로토콜을 변경하면 Dart 저장소뿐 아니라 두 네이티브 저널과 브리지 생성물도 함께 확인한다.
네이티브 변경이 포함되므로 Flutter hot reload만으로 새 기능을 설치할 수 없다. 앱을 다시 빌드해 업데이트한다.
성능 수치는 실제 기기에서 따로 측정하며, 에뮬레이터/시뮬레이터의 결과를 실기기 성능으로 간주하지 않는다.

사전 검수 근거와 합격 기준은 [설계 검수](page-turn-design-review.md)에 기록되어 있다.
